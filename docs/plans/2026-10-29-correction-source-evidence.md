# Supporting evidence for an explicit correction

A source directory can establish which year tables exist without establishing an individual date conversion. An operator's private check also does not mean the model read that source. A correction therefore needs a way to fetch a newly verified, registered document while retaining the published owner's original topic and revision history.

Allow an authenticated correction to add at most four distinct approved source IDs. Reject unknown IDs and URLs before enqueue, retain the IDs in the immutable request, fetch every requested document before writing, and stop on missing evidence. Pass the actual source packet to both writing and review; preserve provenance in the publication. Do not modify the old source archive, bypass source checks, substitute a private note for a source read, or reset correction/model budgets.

The first additional record is the official HKO 2023 text table. It has an explicit bounded 30,000-character excerpt allowance because the relevant April row follows the default external excerpt boundary. This is a reviewed source-registry setting, not a user-controlled fetch limit. Complete table reading does not establish other years or fortune-telling accuracy.

Tests cover legacy requests, unknown/prototype/URL IDs, duplicates, bounded lists, deduplicated fetches, rows beyond the ordinary excerpt boundary, unavailable evidence before model use, and native Workflow request-to-research-to-publication propagation. Real production readback must still confirm the source packet and final bilingual publication separately.
