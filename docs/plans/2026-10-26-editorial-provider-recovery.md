# 内容供应故障的隔离与恢复

内容供应商的账户级 401/402 不是某个选题的内容缺陷。让 Workflow 重试同一请求、再换六个选题，会耗掉请求预留和当日尝试，仍无法恢复供应。[官方错误说明](https://api-docs.deepseek.com/quick_start/error_codes/)将 401 定义为认证失败、402 定义为余额不足；恢复需要账户条件改变。

采用共享的内容供应状态：收到 401/402 后保留真实失败并暂停新的内容模型请求，现有十五分钟核对器在到期后最多每小时读取一次官方余额接口。只有明确的 `is_available: true` 才恢复符合条件的任务；读不到、格式错误和权限失败继续记为 unavailable，不把它们当作余额为零。[余额接口](https://api-docs.deepseek.com/api/get-user-balance/)使用 GET，不生成文章。金额、账户标识和凭证都不写入状态或审计。

选择有界余额读取，而不是反复生成测试文章或长时间盲等。租约和条件提交避免重复读取及旧响应覆盖新故障。400/401/402/422 在 Workflows 步骤内使用 `NonRetryableError`；传输和可恢复的服务端错误保留原重试。供应状态在私有运营接口中单独呈现，不影响独立的技术检查、搜索提交或其他无需模型的工作，也不重置预算、失败记录、选题质量或提供方暂停。

另一个独立读取问题是：部分源码维护的对比页有完整双语 HTML，却尚无知识手册 Markdown。对于对比页的精确 Markdown 404，改读同一 owner 的精确 canonical HTML，并记录实际来源 URL。500 等服务错误不能降级为另一个页面。HTML 退路继续使用完整指南合同，不冒充已获取 Markdown 的聚焦合同。

上线前先应用 `0013_editorial_model_provider.sql`。单元回归验证并发、恢复、未知状态、历史故障引导、金额/凭证排除与预算保留；原生 Workflows/D1/R2 测试验证不可重试故障和真实静态对比页读取。部署后读取实际供应状态和技术检查终态。账户恢复和新文章发布仍必须分别取得真实证据。
