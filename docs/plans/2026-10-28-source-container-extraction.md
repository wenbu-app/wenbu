# 保留来源正文中的完整内容容器

来源读取把 `<main>` 与 `<article>` 的起止标签混合匹配。遇到主内容中的多张功能卡，第一张卡的 `</article>` 就提前结束了主内容，后面的说明与限制全部被丢弃。一次真实官方页面回读在同一份 HTML 上复现了 145 字符的结果；这不能当成官方页面没有可读正文。

提取时先去除脚本、样式、注释等非正文，再优先选择完整的 main；没有 main 时选择完整 article。只用同名标签的平衡深度决定容器范围，保留嵌套 article 后的正文；没有完整容器时保留经过清理的全文。带引号的属性值可以包含大于号，自定义元素的同名前缀不作为正文标签。

来源最低文本门槛、响应大小、重定向允许范围、提示注入检查、摘录长度、六小时缓存、模型预算和独立审稿均保持原有规则。已保存的短文本失败不能因代码修复就被改写为成功；下一次正常到期读取有新回执后才能更新来源状态。

回归覆盖 main 中的多篇 article、嵌套 article、前置卡片、脚本与注释中的伪标签、引号属性、不完整容器与自定义元素，并通过实际来源读取及数据库健康记录检查。原始页面和运营回执保留在私有目录。构建、部署、真实来源回执、文章发布及搜索结果分别验收。
