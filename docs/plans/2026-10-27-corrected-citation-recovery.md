# 纠错后旧引用的恢复边界 · 2026-10-27

普通增补保留已公开的旧章节，明确纠错则替换最新增补。后者虽然保留私有不可变 revision，旧 MCP 章节引用只会得到通用的无效章节提示；Agent 不知道应该重新读取哪一篇。

采用带当前正文指针的 `source_superseded` 工具错误。旧引用必须匹配当前公开 owner 的不可变 revision 和有效章节序号，且不能与仍公开的章节冲突。只查询存在性和章节数量，不取出或重新公开已被纠正的正文、标题或来源。未知、跨 owner、含糊 revision 前缀及不存在的章节仍是无效输入。

错误提供当前 document ID、公开 URL、revision 和明确的 `read_library` 下一步。它不包含成功响应的 source 或 content，不进入 Agent 的已核验来源集合。读者需要重新读取当前正文，才能引用新内容；不会把新文字静默挂到旧章节 ID。MCP、CLI 与 Skill 的工具客户端都可以沿此错误恢复，成功输出合同不变。

验证覆盖普通增补旧章节、显式纠错旧章节、错误 owner、伪造序号、含糊前缀、当前正文重新读取和 Agent 来源门槛。原生 D1/Workflows/MCP 集成检验真实纠错事务后的响应。线上使用现有公开文档验证，不为测试触发新文章或真实纠错，不改变排期、预算、审核或搜索暂停。
