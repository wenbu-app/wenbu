# 持续内容生产与增长反馈

目标仍是每天 09:00、15:00、21:00 三个读者任务，中英文同时交付。扩展搜索意图与来源覆盖，让失败后的修补、换题和储备补充继续执行；质量门槛、历史记录、搜索提供方暂停和真实回执保留。

## 诊断

- 旧补题只接纳新 URL，拒绝所有 merge，即使现有主页面有可核验的内容缺口。这会使覆盖逐渐完善的目录返回空候选。
- 一个排期仅两次尝试，每篇仅一轮修补。来源暂不可读或一次事实错误就可能损失整段排期。
- 已发表补充内容没有进入作者读取的静态 ASSETS 原文；再次扩写还可能覆盖此前的补充。
- 待写数量没有区分主题、关键词假设、可读来源与实际可选任务；排期完成率没有成为每日反馈。

## 实现

1. 六个需求方向：八字与历法、易经与问题、塔罗学习、紫微读盘、日签与记录、Agent 与工具选择。每项记录自然中英文关键词、搜索意图、来源和唯一主页面。未实测的词标为研究假设，不编造搜索量。
2. 补题改为每日执行，储备不足时复用核对器每六小时有界补充，最多两轮提案与对抗审题；实质新增任务可以归入已有 canonical。普通换词、换表格和重复案例仍不能成为新文章。独立校验新题、更新、失败与隔离任务的身份。
3. 每篇最多三轮写作/审稿，逐轮保留完整缺陷和修补记录。每个排期最多六次不同尝试，优先尚未尝试的排期，随后补齐失败排期。现有 15 分钟核对器继续调度，不增加另一套发文定时器。
4. 每次实际模型请求先持久化计费预算；每篇最多 12 次、每日最多 120 次，其中补题最多 8 次。预算耗尽记录缺口，下一日继续；不无限循环。三组目标不等于无条件发布。
5. 使用当前完整公开原文；更新以追加的审核通过内容保留原文与既有增强，并以 CAS 提交中英文、不可变版本和搜索跟进队列。
6. 来源可读性、失败原因、完成排期、关键词方向和储备进入状态 API 与每日技术复盘；选题读取实际查询、页面、使用与失败反馈。7/14/28 天复盘继续区分点击、会话、服务端成功、收录与真实 AI 引用。

## 验证与发布

回归第三轮修补、持续补位、并发排期去重、预算失败保护、新旧版本保留、合并选题、跨语言一致性与来源失败处理。使用真实 Cloudflare 原生运行时测试后提交 PR、只读 Grok review、合并部署。线上核对日程、真实模型产出的双语版本、检查终态和搜索队列；不重复 Google/IndexNow 请求，不发送外联。

依据：Google [有用内容](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)、[生成式 AI 内容](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content)。扩大覆盖依靠不同读者任务和原创实例，不能承诺流量或用同义页面制造数量。
