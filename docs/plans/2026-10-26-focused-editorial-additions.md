# 按读者任务校准内容增补 · 2026-10-26

## 证据与问题

抽查公开的 [十神手册](https://wenbu.app/learn/bazi-ten-gods/) 与 [第一次使用指南](https://wenbu.app/learn/first-reading/)，分别对照源码维护的原文和最近通过审核的增补。十神原文已经解释五种生克关系与阴阳配对，新增内容又用完整篇幅介绍参考点和五种方向；首次使用原文已经说明示例、对话、保存和后续行动，增补又重新讲述这些基础流程。两篇增补也有值得保留的新练习，问题在于新增答案被另一本完整指南包围。

代码对新指南与旧页增补使用同一份四节、双语长文合同和相同的最低文本量。它检查完整度，却不能证明每一段有新增价值。Google 的官方建议同样强调原创贡献与读者是否完成任务，并没有偏好的固定字数。[Google helpful-content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)

另一个反馈缺口是：独立审稿可以认为某个增补值得做，但确定性的准入检查发现它的 canonical 已有 ready 任务，仍应拒绝重复预订。过去将审稿的肯定理由当成修补说明，可能令下一轮误以为“现有页面不能增补”，或再次提交同一预订。模式为 new、审稿决定为 merge 的合同不一致也需要明确修正。

原始运营数据、模型回执和逐项抽样记录保存在私有运营目录，不进入公开仓库。

## 方案取舍

1. 保持所有内容都是完整长文：实现简单，但继续迫使一个缺失答案重复背景。
2. **保留完整指南合同，为已核对双语原页的增补使用聚焦合同**：解决缺失答案、保留图解/表格/完整例子及证据，原文继续存在。采用此方案。
3. 每次重写整个 canonical：容易改变旧引用和已有有效内容，不适合日常增补。明确的纠错继续走已有修订入口。

## 实现约束

- 只有服务端认定的 extend 任务，且本轮已读到同一 canonical 的中文和英文原文，才可以进入聚焦合同。模型不能自选较短格式。缺失、错页、截断或外站上下文仍使用完整指南合同，不把不完整原文当作已充分核对。
- 完整新指南维持既有四节及深度门槛。聚焦增补优先二至三节，保留三条证据项、引用核验、图解、表格、完整假设练习、双语 FAQ/术语与真实产品动作。内部长度边界用于避免空壳，不是 SEO 目标。
- 对新增部分检查原页中的长段落原样重复；这只是确定性的最低防线，不能代替对改写和新增价值的独立审稿。明确的纠错可以保留准确且无须修改的旧段落，不强求新增练习。
- 写作、schema 校验、确定性质量检查和独立审稿使用同一份服务端合同。事实、来源、隐私、安全表达与双语对齐门槛继续生效。
- 原文、早先增补、不可变 revision 与 MCP 旧章节引用全部保留。不会自动删文、重写既有文章、修改其日期或改变公共协议版本。
- 准入仍拒绝已有 ID 与 ready 预订。反馈优先解释实际的确定性阻断与已预订任务；new/merge 冲突给出具体模式修正。只有预订、尚未发布的 owner 不能描述为已有正文或提前增补。保留模型意见与历史，但不把肯定意见当成拒绝原因。
- 不改变文章排期、补题冷却、策略版本、模型预算、提供方暂停或搜索提交频率，不为验证强行生成文章。

## 验证与效果边界

单元回归覆盖服务端选型、错页/缺少原文、新文不得使用聚焦门槛、证据/来源/双语/占位符/确定性承诺检查、原文重复与纠错例外，以及预订和模式反馈。原生 Workflows/D1/R2 集成模拟一次聚焦增补，检查写作与审稿合同一致、双语原子发布、旧文完整保留和旧 MCP 引用仍可读取。

部署后检查精确 Worker 版本、技术检查终态和公共内容格式。测试使用的模型响应是合成输入，不能作为真实文章效果。后续沿既有排期抽查新合同实际产出的新增答案，按成熟时间窗核对真实访问和服务成功；不从篇幅变化推断排名或流量改善。
