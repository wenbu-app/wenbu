# 产品体验与内容增长：2026-10-25

这轮优先打通三条实际使用路径：带着问题开始、从文章继续探索、在自己的 Agent 中使用工具。保留纸感、墨色、原始牌面和中英文内容，不用重做品牌来掩盖流程问题。

## 诊断与取舍

| 观察                                            | 用户遇到的障碍                                   | 本轮处理                                                     |
| ----------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| 桌面 Agent 首屏固定三栏，示例与真实结果共用右栏 | 对话拥挤，示例像已经生成的结果                   | 默认专注对话，结果按需展开；完整示例独立打开                 |
| 新指南追加在搜索区域之外                        | 新文章无法用现有分类、搜索和列表找到             | 每个 canonical owner 只有一张目录卡；新旧内容统一检索        |
| 文章与产品只是泛化按钮相连                      | 读者需要重新解释刚读到什么                       | 带上明确选择的公开指南，用可见问题继续；草稿保留             |
| 排盘约定埋在详情里                              | 把时间假设或不同换年规则当成错误                 | 提前展示时区、未知时刻、换日与太阳时；区分农历生肖和立春年柱 |
| MCP、CLI、Skill 和网页说明分散                  | 无法快速确认能用什么、是否成功、是否涉及私人资料 | 统一版本能力清单、输出结构、连接诊断与来源阅读范围           |

今天已核验的经营数据和截图留在私有运营目录。文章进入会话的样本仍小，不足以判断排名趋势、转化提升或某个竞品词的市场规模。CTA 点击只能说明点击；实际使用须匹配之后的服务端成功事件。界面变更上线也不等于搜索收录或 AI 引用。

## 内容围绕任务组织

| 读者任务                   | 内容主线                             | 独有价值与产品动作                                       |
| -------------------------- | ------------------------------------ | -------------------------------------------------------- |
| 不知道从哪里开始           | 第一次使用、如何提问、工具选择       | 一个完整且无需个人资料的示例；明确进入对话               |
| 同一生日排出不同命盘       | 出生时间、时区、交节、换日、未知时辰 | 对照已核对的计算案例；保留约定再排盘                     |
| 看懂抽到的牌，而非反复抽牌 | 正逆位、人物牌、牌阵、记录与复盘     | 保留原牌的小练习；从这份结果继续问                       |
| 给自己找到每天可做的小事   | 日签与观察记录                       | 一个行动和回看问题；避免伪装成个性化运势预测             |
| 在几个产品之间做真实选择   | 按具体任务比较官方可核对能力         | 给竞品合理评价，写明核对日期与未测试范围；链接适合的工具 |
| 把工具接入自己的工作流     | MCP、CLI、Skill、公开知识格式        | 可运行的合成例子、输出结构、错误与隐私边界               |

近义题优先补充唯一的现有主页面。每个新题必须说明现有页面解决不了什么，提供一个经过核对的案例、图解或比较；不能只换关键词。热点只有在原始日期、原文和读者任务都成立时进入候选，不靠节日数量凑满排期。

## 实验与复盘

1. 首次体验：观察完整示例打开、首次 Agent 发送、终态成功与等待补充资料。比较相同语言与设备，不把展示次数当使用人数。
2. 阅读到使用：观察文章进入会话、工具或对话入口点击，以及进入之后的服务端成功。对来源明确的成熟内容按 7/14/28 天复盘，同时注明样本量。
3. 接入体验：以 CLI `doctor`、固定六爻调用、资料搜索和精确章节阅读验证连接。诊断不调用模型，不读取账号资料；测试请求明确标记，不混入正常使用数据。
4. 搜索与回答引用：分别观察 Google/Bing 请求受理、实际收录、曝光点击、访问，以及真实 AI 回答的品牌提及和引用 URL。爬虫、普通搜索、MCP 请求不能替代 AI 引用证据。

沿用现有每天三个主题、中英文成对发布与质量检查；不新增定时器。周三/周日沿用固定中英文中立问题，不加品牌词、不重复派发。周日复盘把经核验的任务、查询、页面、决策和来源写入已有 observation 顶层投影，后续选题实际读取。至少两周合格储备是准备目标；来源或内容质量不足时顺延。

## SEO、GEO、AEO 的边界

- 保持可抓取正文、唯一 canonical、正确 hreflang、目录内链、完整 Markdown/JSON、来源日期和具体答案。问答段落是为读者解决问题，不保证特殊富结果。
- Google 对 AI 搜索仍要求通常的技术与有用内容基础；不需要创造专用 AI schema。`llms.txt`、MCP 和开放格式提供可读性，不是排名信号的证明。
- Bing AI Performance 的提供方引用统计与中立问题抽样各有范围；保留问题、市场、模型、时间与来源覆盖的限制。
- 不额外全站提交，不重置 IndexNow 暂停，不把部署或成功提交当作收录。已有官方支持申请继续保持用户指定的未发送状态。

依据：[Google AI features](https://developers.google.com/search/docs/appearance/ai-features)、[helpful content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)、[Bing AI Performance](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/)。

## 英文专业用语复核

排盘中的英文十神改用可对照的传统关系名称，中文原名继续保留在数据与提示中。此前的 Opportunity、Intuition 等泛化词不能替代偏财、偏印的名称，也不应暗示测得了人的机会或直觉。术语参照 [Joey Yap / Mastery Academy 的公开英文样本](https://masteryacademy.com/estore/UserGuide/BZCareer/sampleDYDCareer.pdf)；仅核对命名，不采用该产品关于职业或性格有效性的主张。四柱计算与十神对应仍由既有规则表产生，并以固定样本回归。
