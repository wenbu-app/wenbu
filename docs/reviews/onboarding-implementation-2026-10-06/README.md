# 引导与试用第一阶段实施

日期：2026-10-06。依据[已复核的体验研究](../../research/onboarding-trial-experience-2026-10-06.md)。**当前状态：第一阶段实现、修正版 CI、Cloudflare 发布及下列生产核验已完成。** 首轮真实模型验收发现正文选择题被误记为完成，已补修、重新部署并复测；原失败证据保留。

## 复核后的实施范围

保留现有每日额度、独立工具、原始牌面和账号保存机制。先减少试用过程中无效的往返，不在同一版本加入免费澄清额度或转化实验。

1. 服务端约束 `ask_user`：首次可问一个必要的意图问题；上一条 assistant 尚未交付结果时，不允许再以可选方法或风格问题阻塞答复。已完成有内容的回合可以重新澄清新话题。旧客户端没有完成提示时保守处理。真正缺少八字/紫微输入仍可打开对应表单；八字未知时刻有效，紫微必须有时刻和传统参数。拒绝的工具批次不会同时抽牌，不显示成一次工具失败，在原有模型预算内重试。不会根据客户端历史提示返还或增加额度。
2. 首答提示改为摘要、最多三项要点和一个下一步；明确要求详细研究时保留深度。篇幅目标是编辑指令，不靠截断正文隐藏局限。模型仍可能输出不理想的文字，不能承诺每次恰好三项。
3. 完整文字答复作为原消息的结果视图，可在手机、桌面、历史和导出中查看。稳定 ID 来自原消息，保持文本原样，不额外调用模型，不变更保存回执。等待、错误、停止和截断状态不冒充完整结果；已有校验通过的报告/命盘仍保留。
4. 增加两份中英文编辑示例：星星牌反思、未知出生时刻的八字说明。明确区分示例和个人结果，不调用模型或扣回合；保留资料出处和限制。
5. 四个开场白写明可交付目标，点选直接发送可见文字，保留未发送草稿。英文手机用纵向行卡，模式用途对触屏也可见。
6. 出生表单按八字/紫微显示必要字段；高级计算约定折叠但当前约定可见；时区保留 IANA 输入和友好说明。底部操作固定，控件滚动留有空间。取消不提交修改，补充资料后沿用现有直接发送流程；不分享出生资料时可以直接改看通用示例，发送文字与该选择一致。
7. 观察事件区分静态示例操作、答复首块实际可见、服务终态和账号保存。兼容旧页面事件版本。见[口径定义](../../analytics.md#2026-10-06-引导体验观测)。

- 原生键盘日期编辑、关闭再打开已核验值保留。自动化 `fill()` 在这个 IAB 的日期控件只改 DOM 值，追加原生方向键操作后才产生真实输入事件；不把前者误当成产品数据丢失。
- [Grok CLI](grok-review.txt) 只读审查在 90 秒期限内未返回结论，**没有 Grok 通过结论**。本地测试与人工代码复核独立记录。
- 没有真实用户研究或转化 A/B 数据，没有宣称注册、留存或流量已经增长。没有增加数据库迁移或更换密钥。

## 真实模型发现与补修

[第一轮生产验收](live-agent-guidance-initial.json)失败：DeepSeek 把提问及 A/B/C/D 选项直接写成正文，没有调用 `ask_user`，服务端因此发出 `complete`。这是真实的状态识别缺陷，不能用放宽测试条件掩盖。

修正版在发送正文前检查明确的短选择菜单：要求问题、2–4 个连续选项和指向用户回复的句子。首次可选澄清转换为标准问题事件与 `waiting`；用户已经回答时，阻止重复问卷并在既有五次模型调用上限内要求产出内容。持续不遵守时明确失败，不伪报完成。普通行动建议、引用与代码示例保留原样。已有真实报告等成果继续保留。

同一规则用于旧记录的结果视图与对话完成提示，不修改原记录或签名回执。新增中英文问卷、重复问卷、调用上限、普通建议和旧记录回归。正文只在响应完整并校验后显示；已到达的工具结果与真实进度仍可先显示。截断文字不会以完整答复出现。该规则覆盖已观察到的明确菜单模式，并非声称可识别模型所有可能的提问表达。

第一版源提交 `c3d8ffa5397953096086d503b95b5adda3e9b8b9`，Worker `d39e5e22-0499-42af-a347-4ebf6dac0a31`。PR #16 与 main 的 CI 均通过；首轮路由、计算、MCP、分析和账号接口核验通过，但真实模型项失败，**不能视为整体验收通过**。修正版的最终部署回执和复测结果另列。
