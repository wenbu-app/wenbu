# 策略与更新逻辑审查 · 2026-10-25

本轮将代码、Cloudflare 排期、模型预算、内容归属、发布事务、反馈输入和现有 Codex 长期任务逐项对照。下面的缺陷是可复现的故障路径；未把测试场景表述为已发生的线上事故。原始回执、经营数据和定时任务私有配置保存在私有运营目录，不进入公开仓库。

## 发现与修复

| 优先级 | 问题及触发条件 | 修复与回归依据 |
| --- | --- | --- |
| P1 | 补题派发检查通过后，内容任务先取得租约。补题在进入错误处理前失败，没有留下尝试记录；固定实例随后被重复派发而没有新执行。 | 将占锁失败纳入持久化记录，保留对方租约且不消耗模型预算。同一实例的重复调用不能覆盖 live started 记录或抢占其租约。普通六小时冷却保持不变；仅启动占锁可十五分钟后用新实例恢复。`editorial-recovery-audit.test.ts` 覆盖完整竞态和恢复。 |
| P2 | 批量创建 API 跳过已有实例，但返回成功被表述为新排队。 | 检查实际创建的实例列表；若已存在，读取并返回其真实状态，不重启、不删除历史。 |
| P2 | 每日增长复盘只保存一次，白天新增失败与储备变化不能进入当日后续规划。 | 按当天的状态指纹追加不可变快照；相同证据去重。补题读取信号前刷新来源与复盘。回归验证新失败生成新快照，旧记录保留。 |
| P2 | 多轮拒稿的同一 ID 取到了较早批评，版本与任务描述可能错配。 | 在每轮决定时记录该版任务及批评，后续输入按 ID 取最新未解决版本，已修复通过的 ID 不再作为未解决项。 |
| P2 | 为满足输入上限直接截取 JSON 字符串，可能截断结构、链接或时间窗。 | 压缩完整字段后再序列化，始终生成不超过 6000 字符的有效 JSON；保留完整 URL，必要时明确省略整个字段。完整证据不受影响。 |
| P2 | 来源条数允许重复 ID 或同一文档的片段别名，夸大候选储备或推迟到写作时才失败。 | 模型候选拒绝重复 ID；候选准入、储备和实际读取按不同注册文档计数。两份文档是最低证据门槛，不等于两家独立机构或专家评审。 |

Cloudflare 文档明确说明旧数组形式的 `createBatch` 会跳过重复实例 ID，不能用“调用未抛错”证明创建成功。保持当前受测的 SDK 形式，先修正回执处理，没有为本次审查进行无关依赖升级。[Cloudflare Workers API](https://developers.cloudflare.com/workflows/build/workers-api/)

## 保持的策略

| 范围 | 决策和实际边界 |
| --- | --- |
| 产量与节奏 | 每天 09:00、15:00、21:00 三个中英文主题；新文和实质更新分别记录。未到期的排期不算失败，尝试数不算发布数。 |
| 预算与恢复 | 每篇最多三轮写作/审稿、每个当天排期六次尝试、每篇十二次物理模型请求、每天 120 次，其中补题最多八次。冷却或预算到期前不伪造执行。旧缺口留在历史，不跨日无限追发。 |
| 选题与关键词 | 六个读者任务方向；种子词和模型扩展词是研究假设。真实查询须保留提供方、语言和时间窗，不能编造搜索量。新竞品来源仍需原文核验后加入注册目录。 |
| 内容归属 | 近义词共享 canonical。实质缺失答案增强原页；改版式、替换数字或换品牌名称不能充当独有价值。 |
| 事实与解释 | 计算约定、传统诠释、厂商自述与编辑建议分开。模型不得代替历法运算，也不得宣称经过验证的预测准确率。 |
| 发布与 Agent | 中英文原子发布、CAS 防覆盖、旧版本和旧章节引用保留。公开 HTML、Markdown、JSON、目录、sitemap 与 MCP 读取得到分别验证。 |
| SEO/GEO/AEO | 技术可读性与真实答案价值并行。提交受理、实际抓取/收录、排名、访问、服务成功和真实 AI 引用分开核对，缺失数据保持 unknown/unavailable。 |
| 分析与归因 | 浏览器、爬虫和 Agent 分开；CTA 点击不算服务完成。7/14/28 天复盘使用成熟样本，样本量和覆盖缺口必须明确。 |
| 长期迭代 | 沿用现有早晨/夜间任务；私有账本保存未完成项、证据、验证与下一动作。内容执行在 Cloudflare，工程与登录浏览器任务仍依赖其执行主机及权限。 |
| 权限与隐私 | 不新增文章或 IndexNow 本地定时器；不发送社交、外联、邮件或已被用户暂缓的支持申请；不重置提供方暂停和历史回执。 |

## 仍需用真实结果校准

- 审稿模型与写作模型的独立调用不等于独立专家评审。需要继续抽查新增部分相对原页的贡献，避免把可重述的常识当作实质更新。
- 完整度应服从读者任务；当前长文模板仍需通过抽样评估，不能将字数、每天更新或页面数量直接作为搜索效果。Google 明确没有偏好的固定字数，也不认可仅为“显得新鲜”而改日期或增删内容。[Google helpful-content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)
- IndexNow 服务方持续拒绝仍是未解决事项。本轮核对现有暂停与提交记录，没有新增探测 POST，没有声称恢复。200/202 只证明接收或验证处理中，不证明收录。[IndexNow protocol](https://www.indexnow.org/documentation)
- ACTIVE、queued、已入队选题和已通过构建都不是业务增长。需要后续终态、成熟访问与实际服务成功，以及固定问题下的真实 AI 引用样本。

## 验证范围

回归覆盖来源去重、最新反馈版本、压缩后的 JSON/URL/时间窗、占锁竞争、真实实例创建回执，以及同日复盘快照的追加和去重。完整测试继续覆盖原子发布、失败不覆盖已发布内容、模型预算、MCP 旧引用和 IndexNow 暂停。生产核验应读取准确部署版本、技术检查终态和状态回读，不能从测试推断真实流量或模型内容质量。

本轮只读 Grok CLI 检查关闭工具、联网搜索和子代理，在 65 秒内没有返回有效报告，按 unavailable 记录，没有标为评审通过。
